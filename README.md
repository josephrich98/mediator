# mediator

**Two AI agents. One repo. Zero clobbered files.**

`mediator` keeps concurrent coding agents (Claude Code sessions, Codex, Cursor, a human) from overwriting each other's work in the same checkout. It is a 600-line, zero-dependency CLI plus a set of Claude Code hooks. No supervising agent, no LLM calls, no tokens spent when you work alone.

```
$ claude            # terminal 1: "add priorities to todos"
$ claude            # terminal 2: "add due dates to todos"
```

Terminal 2's agent sees this before it touches anything:

```
mediator is active: 1 other agent is working in this repo right now.
  [03f0] "Add priority field to todos" — 3 files: src/store.js* src/cli.js README.md
  (* = has uncommitted edits by that agent; wait for release before touching)
```

And if it tries to edit `src/store.js` anyway:

```
mediator: BLOCKED — src/store.js is currently held by agent [03f0] "Add priority field to todos"
(claimed 2m ago, 3 edits so far).
Do not edit this file now. Options: (a) do your other files first and come back;
(b) run `mediator wait src/store.js` to block until it is released, then Read it again before editing.
```

When agent 1 finishes with the file, agent 2 is told to re-read it. Nobody's edits vanish.

## Install

```bash
npm i -g mediator-cli          # or: npm i -g github:josephrich98/mediator
cd your-repo
mediator init                  # .mediator/ state dir, Claude Code hooks, skill, .gitignore entry
```

That's it. Start as many agents as you like in that repo.

`mediator init` writes hooks to `.claude/settings.json` (merging with whatever is there), copies a 25-line skill to `.claude/skills/mediator/`, and git-ignores `.mediator/`. Nothing happens in repos you haven't run `init` in, so you can also install the hooks in your user-level settings with `mediator init --settings ~/.claude/settings.json --no-skill` and opt repos in one at a time.

## How it works

Every file an agent edits is **claimed** for that agent until its turn ends. Claims live in `.mediator/claims/` as one small JSON file each, created with `O_EXCL`, so *checking* whether a file is free and *taking* it is one atomic operation. There is no daemon and no lock server; the filesystem is the arbiter.

| Failure mode | What mediator does |
|---|---|
| Both agents see a file as free at the same moment | Check-and-claim is a single atomic `open(O_EXCL)`. |
| An agent crashes holding files | Claims die with their owner's process; reservations also expire after 15 idle minutes. Stealing a dead claim uses `rename()` so only one reaper wins. |
| The up-front file list was wrong | Every `Edit`/`Write` passes through a hook that claims on the spot or blocks. |
| Two files depend on a changing interface | `mediator note "<what changed>"` is delivered to the other agents after their next tool call. |
| An agent read a file that another agent then changed | Releasing an edited file logs a handoff; others are told once to re-read it. |
| Shell commands bypass the Edit tool | `sed -i`, `>`, `mv`… aimed at someone else's file are blocked. So are `git stash`, `git checkout .`, `git reset --hard`, `git add -A`, `git commit -a` while others are present. |
| Idle agents hog files | The Stop hook releases everything at end of turn; the next edit re-claims automatically. |

The protocol the agents follow is three cheap habits, taught by the skill and repeated in a ~120-token brief at session start (only when someone else is present):

1. `mediator plan "<one-line goal>" <files>` before the first edit.
2. `mediator note "<what changed>"` after changing a shared interface.
3. On BLOCKED: do other files first, or `mediator wait <file>` and re-read.

## Benchmark

Two headless Claude Code agents (Sonnet 5.5) were given overlapping feature tasks on a small todo CLI, five seconds apart, in the same checkout: one adds a `--priority` flag, the other a `--due` flag. Both must touch `src/store.js`, `src/cli.js`, `src/format.js`, `README.md`, and the tests. Both were told another agent was working in the tree. Acceptance is 18 scripted checks (tests pass, each flag works, each is displayed, invalid values rejected, README documents both, nothing deleted). Run it yourself with `node bench/run.js --condition baseline|mediator --trials 3` and `node bench/report.js`.

## Commands

```
mediator init                         set up this repo (hooks, skill, state dir)
mediator status [--json]              who is here, who holds what, recent notes
mediator plan "<goal>" [files...]     announce your work; reserve files
mediator claim <files...> [--wait]    reserve files (hooks do this automatically for Edit/Write)
mediator wait <file> [--timeout S]    block until a file is free, then claim it
mediator release <files...> | --all   hand files back early
mediator note "<text>"                broadcast an interface change
mediator who <file>                   who holds a file
mediator inbox                        updates from others since you last looked
mediator log                          raw event log
mediator gc                           drop dead agents and expired claims
```

Environment: `MEDIATOR_AGENT` (identity; Claude Code sessions are detected automatically), `MEDIATOR_ROOT`, `MEDIATOR_TTL_SEC` (default 900).

## Works with

- **Claude Code**: full enforcement via hooks (`PreToolUse`, `PostToolUse`, `SessionStart`, `UserPromptSubmit`, `Stop`, `SessionEnd`). Parallel subagents inside one session are tracked as separate agents too.
- **Codex, Cursor, Aider, humans**: cooperative, through the same CLI. See [docs/other-agents.md](docs/other-agents.md). Claims taken from any tool are honoured by the Claude Code hooks.

## Design principles

- **Deterministic over clever.** Overlap detection is a string comparison; the participating agents, not a referee model, decide who yields.
- **Zero cost when alone.** No agents present → hooks print nothing.
- **The board is derived, not edited.** A shared STATUS.md would be its own race. `mediator status` renders from the claim files.
- **Plain files you can `cat`.** `.mediator/` is JSON. Delete it to reset.

More in [docs/design.md](docs/design.md).

## FAQ

**Why not git worktrees?** Use them when tasks are independent. mediator is for when they are not (two features touching the same modules), or when you simply don't want to plan ahead.

**What if an agent needs a file someone else holds for a long time?** `mediator wait <file>` blocks up to 5 minutes by default. `mediator claim --steal <file>` exists for when the holder is clearly gone but its process is still alive.

**Does this slow Claude Code down?** One Node process start (~40 ms) per hooked tool call.

**Does it work on Windows?** Claims and hooks are plain Node; liveness falls back to heartbeats where `kill -0` isn't meaningful. Untested so far; issues welcome.
